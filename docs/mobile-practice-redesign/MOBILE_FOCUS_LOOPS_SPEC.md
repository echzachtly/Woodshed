# Mobile Focus Loops Spec

## Concept

Focus loops are lightweight playback targets inside a parent phrase.

They are not standalone phrases.

---

# Mobile Role

On mobile, focus loops are:
- practice targets
- repetition shortcuts
- contextual playback options

They are NOT:
- editing structures
- nested navigation systems

---

# Display Rules

Focus loops should:
- appear inside the active phrase experience
- remain contextual to the parent phrase
- support rapid switching

They should NOT:
- clutter global navigation
- appear as standalone phrase items

---

# Playback Modes

Supported modes:

- Play Through
- Loop Phrase
- Focus Loop

If a phrase contains focus loops:
- Focus Loop should become available
- the most recent or selected focus loop should become active

---

# Selection Behavior

Selecting a focus loop should:
- immediately activate Focus Loop mode
- require minimal taps
- preserve practice flow

Avoid additional confirmation steps.

---

# Editing Constraints

Mobile should not expose:
- focus loop editing
- creation workflows
- deletion workflows
- precise region editing

Those belong to desktop.

---

# State Persistence

The app should remember:
- last-used focus loop
- last loop mode
- recent speed

This minimizes repeated setup friction.

---

# UX Goal

Focus loops should feel like:
- fast practice presets

NOT:
- nested project structures
