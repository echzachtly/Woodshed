# Woodshed Mobile Practice Redesign Brief

## Purpose

The mobile version of Woodshed is the dedicated practice environment for the platform.

Desktop exists for:

- creating phrases
- editing loops
- organizing practice material
- creating focus regions
- authoring practice workflows

Mobile exists for:

- practicing
- repetition
- flow state
- quick access
- focused musical interaction

The mobile app should not become a compressed desktop editor.

This separation is a foundational product principle.

---

# Core Product Philosophy

Woodshed mobile is not:

- a DAW
- an audio editor
- a project management app
- a timeline editing tool
- a media library browser

Woodshed mobile IS:

- a deliberate practice tool
- a repetition-focused practice environment
- an interactive musical playback surface
- a hands-free-aware practice companion
- a focused audio workflow tool

---

# Mobile Identity

The mobile experience should feel:

- immediate
- tactile
- musician-native
- low-friction
- calm
- fast
- focused
- touch-friendly
- repetition-centric

The app should support sustained practice sessions with minimal interruption.

---

# Desktop vs Mobile Separation

## Desktop

Desktop is for:

- phrase creation
- focus region creation
- waveform editing
- precise organization
- practice workflow authoring
- project management
- structural editing

## Mobile

Mobile is for:

- practicing phrases
- restarting quickly
- switching focus loops
- changing speed
- freeform waveform practice
- staying in musical flow
- hands-free-aware interaction

---

# Repetition Is The Core Workflow

The mobile app is fundamentally built around repetition.

Every extra tap interrupts practice.

Reducing friction is a primary UX goal.

---

# Hands-Free Practice Philosophy

Many musicians cannot comfortably interact with a device while actively practicing.

The mobile experience should prioritize:

- large reliable controls
- low interaction cost
- rapid restart behavior
- persistent controls
- quick loop switching
- future hands-free support direction

Future footswitch support is considered strategically important.

---

# Waveform Philosophy

The waveform remains an important interactive surface on mobile.

Users should be able to:

- seek through songs
- scrub
- tap to navigate
- visually orient themselves
- practice freely without structured phrases if desired

Mobile should support:

- practice interaction
- navigation
- playback targeting

NOT:

- precise editing
- dense waveform manipulation
- complex region authoring

---

# Structured Practice vs Freeform Practice

The app should support two valid mobile practice styles.

## Structured Practice

Using:

- desktop-created phrases
- desktop-created focus regions
- saved practice targets

## Freeform Practice

Using:

- waveform navigation
- ad hoc looping
- speed changes
- exploratory listening/practice

Users should not be forced into phrase-driven workflows.

---

# Focus Regions Philosophy

Focus regions are internal practice targets inside phrases.

They are NOT standalone navigation objects.

On mobile, focus regions are playback targets, not editing structures.

---

# Lead-In Context Philosophy

Traditional count-ins are not the primary direction.

Instead, Woodshed should support musical lead-in context.

Example workflow:

- user presses play
- playback begins several seconds before the phrase
- user hears natural musical context
- phrase arrives naturally
- phrase then loops normally

---

# Looping Philosophy

The app should support contextual playback modes such as:

- Play Through
- Loop Phrase
- Focus Loop

---

# Interaction Philosophy

The mobile experience should prioritize:

- single-tap actions
- muscle-memory interaction
- rapid repetition
- low cognitive load
- persistent context
- minimal navigation friction

---

# Landscape Support Philosophy

Portrait orientation is the primary mobile experience.

However, landscape usage should be intentionally supported.

---

# PWA Direction

The mobile experience should move toward a strong Progressive Web App (PWA) experience.

Priority goals include:

- install-to-home-screen support
- app-like launching behavior
- fullscreen app presentation
- strong mobile responsiveness

---

# Product Direction Summary

Desktop is:

Practice Authoring

Mobile is:

Practice Execution
